Product Requirements Document  ·  Section 9

Screen-by-Screen
Specifications

9 screens 7 user-facing  ·  2 admin Elements  ·  Actions  ·  Acceptance Criteria
01
Landing Page
User-facing
▶
Elements
  • Headline + subheadline in plain language
  • Live anonymised earnings ticker
  • 3-step "how it works" section
  • Payout SLA badge
  • "Start Earning" CTA above the fold
  • FAQ anchor link
Actions
  • "Start Earning" triggers Google OAuth
  • Returning users redirect to dashboard automatically
Criteria
  • LCP under 2 seconds
  • Ticker refreshes every 30s from real ledger
  • CTA visible without scrolling at 375px width
02
Google OAuth / Sign-Up
User-facing
▶
Elements
  • Google OAuth popup via NextAuth.js
  • No custom form fields
Actions
  • Select Google account
  • Approve required permissions
Criteria
  • New user record created under 500ms
  • Device fingerprint captured on page load
  • First-timers → tutorial · returning → dashboard
03
Sandbox Tutorial
User-facing
▶
Elements
  • 3-step guided overlay
  • Simulated task card + fake URL input
  • Tooltips at each step
  • Progress indicator
  • "Complete Tutorial" button on step 3
Actions
  • Follow guided steps
  • Paste a practice URL
Criteria
  • Dashboard route-guarded until tutorial_completed = true
  • Cannot be skipped
  • Renders correctly at 320px min width
04
Main Dashboard
User-facing
▶
Elements
  • Wallet summary card (Pending, Available, Lifetime)
  • Queue of 5 task cards with type, payout, est. time
  • "Accept Task" CTA per card
  • "Refresh Queue" button
  • Tasks completed today counter
Actions
  • "Accept Task" → Redis lock + opens Task Detail
  • "Refresh Queue" → fetches a new batch
  • Wallet card → opens Wallet screen
Criteria
  • Queue loads in under 1 second
  • Taken slot shows toast, card swaps without full reload
  • Minimum 48px tap targets on mobile
05
Task Detail
User-facing
▶
Elements
  • Full task instructions as formatted HTML
  • Required keyword highlighted inline
  • Target URL + payout amount
  • Lock countdown synced to server TTL
  • "Submit Proof" CTA + "Return to Queue" button
Actions
  • "Submit Proof" opens Submission screen
  • "Return to Queue" releases Redis lock via API
Criteria
  • Countdown is server-synced, not client-computed
  • Instructions rendered as formatted HTML
06
Task Submission
User-facing
▶
Elements
  • URL input with inline format validation
  • Helper text below input
  • "Submit" disabled until format passes
  • Async URL preview thumbnail
  • Resubmission note shown on retries
Actions
  • Paste URL → instant client-side regex
  • "Submit" → triggers async 4-tier validation
Criteria
  • API returns 200 OK / SUBMITTED under 500ms
  • Result polled every 5s for up to 60 seconds
  • After 60s → "Still processing — check History shortly"
07
Wallet
User-facing
▶
Elements
  • Available balance (prominent display)
  • Pending balance in muted style with 24h-hold tooltip
  • Lifetime earnings total
  • Transaction history paginated at 10 per page
  • "Withdraw" disabled + tooltip when under $10
Actions
  • "Withdraw" opens withdrawal flow
  • Tapping a transaction opens detail modal
Criteria
  • Ledger query renders under 200ms
  • Pending and Available visually distinct at a glance
08
Admin Task Upload
Admin
▶
Elements
  • CSV drag-and-drop zone
  • Template download link
  • Parsed preview table with error rows highlighted
  • Visibility settings (Active / Scheduled + date picker)
  • "Publish Tasks" CTA
Actions
  • Upload CSV → review errors → set schedule → publish
Criteria
  • CSVs over 500 rows run as background job with email confirm
  • Error rows show specific column + reason
  • Publish is atomic — all or nothing
09
Admin Monitoring Dashboard
Admin
▶
Elements
  • KPI cards — tasks today, pass rate, payout queue, active users
  • 7-day completion trend chart
  • Flagged users table (fraud score + signal breakdown)
  • Dispute queue + payout status table
Actions
  • Click flagged user → full history + signal log
  • Resolve dispute → one-click approve or reject
  • Manually retry a failed payout
Criteria
  • Auto-refreshes every 60 seconds
  • Ban requires mandatory reason field before confirming
